# Preview retention and PR liveliness

The cleanup controller previously had no administrator-editable retention policy.
This change adds `/admin/preview-retention` and the same shared sections to
Settings → Admin, backed by a fresh home-plane settings singleton with revision
comparisons. It now uses the existing SettingsDocumentHost/accountSettingsDocumentAdapter, WebpageBlocksRenderer and TransientBlockHost. Every title, description, label, hint, input, checkbox, conditional section and action button is an independently editable block; the host retains only scoped policy operations and display state. Layouts are private saved webpage Things, with the normal Builder revision fence.

Defaults enable cleanup of previews without an open PR, with no grace. Pruning
superseded active-PR previews and expiring inactive open-PR previews are optional.
Inactivity uses GitHub PR `updated_at`, never closes the PR, and suspends preview
publishing until activity resumes. Protected controller implementation is in
[PR #1294](https://github.com/lopugit/thingtime/pull/1294); it consumes the signed
policy and preserves deployments if policy retrieval or validation fails.

Both new routes have independent 1.0.0 capabilities generated by both canonical
manifest implementations. Admin writes require JSON, current admin access and
expected revision. Controller reads require the router HMAC, exact repository,
protected ref and fresh timestamp, with a bounded unsigned input stream. Response
headers prohibit caching. Controller responses omit storage/audit metadata.

Viewer and selected API-origin changes unmount the inner editor immediately via
canonical root identity generations; transport carries expected actor/origin.
Delayed old reads and save acknowledgements cannot repopulate a new scope.

Local acceptance exposed an existing Nitro startup failure: shared schema imports
reach browser WASM engines, and eager unwasm initialization prevents the API
runner from becoming ready. Supported `wasm.lazy` fixes startup while preserving
the actual Vite-generated engine URLs and valid WASM bytes for both engines.

## Rollout and limitations

Ship the product gateway API first and verify authenticated save/readback on the
selected production origin. Then ship protected-controller PR #1294 and run its
safe reconciliation acceptance. A normal UI preview forwards to the existing
gateway and cannot prove the new API before that rollout. Neither PR authorizes
remote primary-branch changes. Parent owns the separate provider-cleanup audit.

Task branch `codex/mongo-preview-cleanup` began at freshly fetched origin/main
`530af14061611ad9c547041a2aea994343459a10` in its own managed worktree. Local
acceptance used ports 18210/18211/18212 and a disposable replica at 17343; task
browsers and processes are cleaned up after verification. A Funnel was not
provisioned for the isolated admin fixture.
