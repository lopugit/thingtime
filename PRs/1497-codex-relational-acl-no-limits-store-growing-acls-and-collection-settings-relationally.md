# Store growing ACLs and collection settings relationally

[PR #1497](https://github.com/lopugit/thingtime/pull/1497) repairs the production reporting preparation failure `acl can have at most 64 entries`. A shared private workspace reference had two audience markers and 62 task Character grants. The next grant failed, and the original external task remains the recovery target.

Growing audience and token grants are protected child Things with separate generations and revisions. The root carries a finite logical baseline and a legacy-reader compatibility fence. The new server does selective subject lookups, preserves exclusion precedence and current-root validation, and exposes an owner-only paged mutation/read API. Full ACL responses, Timeline snapshots, copies and backups remain complete for clients talking to the new server. Old server deployments deliberately deny nonowner reads of migrated public/custom Things. A strict database validator rejects older explicit ACL writers that would overwrite the fence; a protected monotonic timestamp floor prevents stale conversion replacements from removing it.

A signed-negative logical `-tt:all` marker is private, even though its raw index hint contains `tt:all`. Candidate queries must retain that owned Thing for authorized private-visibility PAT and circle reads without treating it as a positive public grant. The post-review focused test and built-server boundary smoke are release checks for this case.

The same task moves selected app grants, app origins/callbacks, encrypted account endpoints/deployment links, subspace definitions and learned algorithm weights into protected relational records. It removes arbitrary total count limits or truncation from relational groups, social edges, subspace memberships, invitations, reactions, pins, owned subspaces and custom flair choices, plus authored schema and Component count limits. Existing validation, rate controls, transaction accounting, owner checks and selected-origin boundaries remain in force. See [the contract and rollout notes](../docs/relational-access.md).
