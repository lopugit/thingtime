# PR 799 — Searchable admin error-log Things

Moderation errors previously reduced upstream failures to HTTP status and a small code allowlist. A 429 with only an error type/message lost its reason, preventing reliable diagnosis of the failed invitation avatar review.

The new server logger stores protected `error-log` Things in the home database. Shared handled failures, registered API exceptions/5xx responses, and OpenAI/Anthropic moderation failures capture a redacted closed error snapshot. Server-generated request IDs correlate the provider event and final response; upstream codes, types, request IDs and retry delay remain available. Input images, text, credentials, full request bodies and arbitrary SDK objects are not captured.

Current admins can search `/things?logs=1`, expand wrapped details and page older records. Every read rechecks admin status, returns private/no-store headers and excludes expired records. Generic Things ACLs, search, feeds, export and mutation cannot expose or alter logs. Logs are non-billable control records, expire after seven days, and share the home-only ephemeral TTL and existing general Thing paging index. Persistence is best effort with a one-second deadline, five concurrent writes, five records per request and 60 writes per minute per instance; console metadata survives persistence failures and caps.

Validation: all 3,014 unit tests passed after the shared-index and schema fixes; full production build and Vercel output checks; eight logging/security tests; 58 moderation tests; collection/index, client-error, capability and invitation suites; 18 live read-only admin API checks. Local Chrome desktop (1280px) and mobile (390px) checks covered search, expanded detail wrapping, full-page scroll and revocation of the temporary local fixture's admin privilege. The privilege was restored afterwards. Typecheck reports 111 existing errors against the 108 baseline, with none in the changed implementation. The local checkout has no OpenAI credential, so production diagnosis follows deployment.

The logging capability is `api.admin-error-logs@1.0.0`. No content migration or new credential is required; the normal boot index ensure replaces the old diagnostic TTL with the shared ephemeral TTL without increasing the steady index count. The logger is a bounded diagnostic trail, not an exhaustive audit ledger. This PR does not infer that a free moderation endpoint's 429 is caused by billing.

The shared repo `AI_ALL.md` now requires minimal, high-level Thing indexing, reuse of common property paths, evidence-backed exceptions and strong performance optimization. Logs add no steady-state index slots: their paging order matches the existing `{ thingtime: 1, createdAt: -1, shareId: 1 }` index, while one generalized root-expiry index replaces the old diagnostic TTL. The explicit disposable-kind registry excludes invitations and attachments that require refund/accounting/object cleanup.

Live local `explain('executionStats')` selected `thingtime_1_createdAt_-1_shareId_1` with no blocking sort (one matching fixture returned, one key/document examined, 2 ms). This verifies index eligibility and ordering on the small fixture, not large-volume latency. Local boot convergence installed the generalized expiry policy successfully. The first CI pass caught the new schema missing from the pinned projection table; the table now covers all error-log metadata fields.
