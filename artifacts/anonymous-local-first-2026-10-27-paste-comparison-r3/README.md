# Native instruction paste diagnosis — 27 October 2026

The normal Settings instruction editor still fails the unchanged under-five-second native paste gate. Every completed case preserved the exact 120,068 UTF-8 bytes / 12,002 lines, native undo and redo. No speculative editor change is included.

- [First comparison](../anonymous-local-first-2026-10-27-paste-comparison/run.log): fresh Settings took 2,592 ms. The plain control could not be found on the diagnostic route. Blocking service workers in the separate diagnostic context resolved that setup failure, consistent with route interception. That failed fixture is retained.
- [Matched comparison](../anonymous-local-first-2026-10-27-paste-comparison-r2/paste-compare/paste-comparison.json): separate plain-control contexts block service workers so the diagnostic route works; the product context is unchanged. Fresh Settings 3,348 ms; Settings after editing history 8,758 ms; matched plain textarea 259 ms; matched plain textarea without spellcheck 268 ms. Plain controls are diagnostic only, not native Thingtime renderer acceptance.
- [Same-document comparison](paste-compare/paste-comparison.json): normal Settings after editing history 10,388 ms; a cloned native textarea in the same product document 3,477 ms. Both use the same preceding values, fonts/styles and actual clipboard operation. The clone is a disposable DOM diagnostic, not a shipped replacement.
- [Product trace](paste-compare/settings-history-trace.json): Chromium `ReplaceSelectionCommand::doApply` spans 9,992.707 ms inside the paste; the large delay precedes the input event. [Clone trace](paste-compare/settings-clone-history-trace.json): 3,281.314 ms. Trace artifacts retain only event name/category, duration/time and process/thread fields. Nested durations must not be summed.

The Settings control is a controlled Chakra textarea; its change handler updates one draft row and persistence begins on Save. No custom paste/beforeinput/autosizing handler was found. These observations narrow the problem to native editing in the product document and its edit history/ownership, but do not yet identify a safe fix. A useful next check is controlled/defaultValue synchronization versus a native control with the same sequence and document.

All runs used the previously built `b5ed654c` application package with only diagnostic test code changed. Each retains package, network boundary, resource and cleanup records. Browser/backend direct-IP, IPv6, hostname and redirect egress checks remained denied, Chromium sandboxing stayed enabled, no OOM occurred and each owned container was released. Only disposable synthetic identities were used. No installed macOS, provider or production acceptance is claimed.
