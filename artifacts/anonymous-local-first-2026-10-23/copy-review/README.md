# Local copy and capacity follow-up

The normal account copy/fork facade now imports complete scoped file export plans through the existing Blob pipeline and atomic importer. Copied content and files receive new IDs, executable/media bindings are rewritten, and ordinary content/file intents commit together. Canonical file aliases map to the copied root without positional assumptions. The normal folder-delete path now drains standalone files through the dedicated metadata queue rather than the generic Thing writer.

Browser Actions support bulk copy for editable definition/Data/folder closures through the same interpreter and leased writers. Account Action copies require complete device export content and never invoke the remote adapter; protected child content is refused before writes. Ordinary local move/delete/copy facade selections no longer have an independent 200-ID ceiling; cycle detection remains for deep folder traversal.
