WHEN YOU NEED A HAND

Using Thingtime passkeys

Get connected

  1. Enable website passkeys in Config and select your trusted Thingtime origin.
  2. Reload the website, then open this workspace from its toolbar button.
  3. Start the website’s passkey action. Complete the approval in Thingtime.

Another extension can own the hook

If Overview says a hook could not install or was replaced, another extension or the page may control WebAuthn. Turning off another provider’s passkey prompts may still leave its hook installed. Choose your preferred browser extension, then reload the website. Thingtime never overwrites an immutable hook.

Your native macOS password-provider settings are separate from browser extensions.

Native fallback is available

Conditional sign-in and unsupported request options use the browser’s native provider. In Requests, you can also choose another provider explicitly. A credential appears only when it matches the website’s relying party and allowed credentials.

Private by design

This extension stores your opt-in, trusted origin and appearance preferences. Its redacted account list stays only in memory while the owned Thingtime connection is live. Temporary routing handles identify the requesting document. Passwords, private passkey keys and account sessions stay out of extension storage.

No completed-request history is retained. Connection diagnostics are page-reported hints, never permission to use a credential.
